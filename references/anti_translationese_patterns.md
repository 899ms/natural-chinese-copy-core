# 翻译腔与 AI 腔拦截规则

目标：识别句子骨架的问题，而不是只做禁词替换。

## 1. 核心判断

翻译腔常常不是某个词错了，而是整句话仍然按英文产品页的顺序在走。

出现下面情况时，先重写句子主干，再考虑删词：

- 先定义产品，再堆功能，再给抽象结论
- 用项目名硬当推荐句主语
- 用项目名硬当读者动作的主语
- 用抽象名词代替具体动作
- 用假口语制造亲近感
- 用金句式转折制造高级感
- 用 heavy / light 隐喻评价流程、系统、工具
- 用过长条件状语抢在主动作前面

## 2. 硬拒绝骨架

拒绝这些结构，即使换了近义词也要重写：

- `不是 A，而是 B`
- `比 A 更 B`
- `我更在意 / 我更关心`
- `不只是 A`
- `不只是 A，而是 B`
- `不只是 A，还包括 B`
- `不只是 A，还要 B`
- `最...的地方，是...`
- `有意思的地方，是...`
- `更值得看的不是 A，而是 B`
- `真正值得看的，是...`
- `真正 X 的是...`
- `真正重要的是...`
- `真正麻烦的是...`
- `重要的不是 A，而是 B`
- `A 一旦 B，就 C`
- `当 A 进入 B 之后，真正的问题是...`
- `流程很重 / 流程很轻`
- `系统偏重 / 工具偏轻`
- `A 把 B 做成 C`
- `A 把 B 放进 C`
- `A 往 B 推`
- `项目名 先看 X`
- `项目名 看一下 X`
- `项目名 值得看 / 值得拆`
- `要理解 X，我们先以 Y 为入口`
- `拆开`
- `更像是...`
- `价值就在这`
- `开始接近...`
- `一层 / 这层 / 接口层 / 管理层 / 组织能力`
- `这件事`
- `日会`
- `走查`
- `这次看`

这些骨架的问题是把判断写得很满，但没有说清具体动作和具体后果。

### 2.0.1 对比骨架

触发：句子写成 `比 A 更容易 / 更清楚 / 更现实 / 更重要`，或者用 `我更在意 / 我更关心` 抬起主观判断。

判断：中文里可以比较，但这类文案常把英文的 comparative argument 直接搬过来。读者先看到作者在比较，后面才看到事实。普通说明、课程资料和社媒短评里，优先写具体动作和结果。

改法：删掉对比关系，直接写结果。

```text
差：代码卡住时回到对应 Notebook 看输入和输出，比只读概念文章更容易定位问题。
好：代码卡住时回到对应 Notebook 看输入和输出，通常能找到卡在哪一步。
```

```text
差：我更在意它跑完以后留下什么。
好：看 agent 产品时，我会先查它跑完以后留下哪些记录。
```

触发：句子只写到 `不只是 A`，后面用 `了`、逗号或句号收住。

判断：这仍然是在铺垫一个英文式对比判断。即使没有写出 `而是 B`，读者也会被带进“先否定旧判断，再抛新判断”的固定姿态。

改法：删掉 `不只是` 结构，直接写新的具体事实、动作或检查点。

触发：句子先写一个反例、旧判断或错误方向，再用 `而是 / 只是 / 但 / 不过 / 却 / 真正` 把正话带出来。

判断：这不是信息推进，而是在制造陪衬。读者需要的是当前事实、真实动作和具体结果，不需要先读一个作者临时摆出来的反面靶子。

改法：删掉反例半句，只保留正向事实，并补出真实动作、对象和结果。

```text
差：现在能查资料、跑代码和处理图片，而不是还要自己把几段能力拼起来。
好：现在可以用同一条调用链查资料、跑代码和处理图片。
```

## 2.1 英文轻重隐喻

触发：用 `重 / 轻 / 偏重 / 偏轻` 评价流程、系统、工具、方案、架构、机制、配置或模块。

判断：这是英文 heavy / light 逻辑迁移。中文读者更需要知道实际麻烦是什么：步骤多、配置多、依赖多、启动慢、审查项少、约束弱、覆盖范围小。单写“重”或“轻”会把具体事实压成一个虚形容词。

改法：把轻重判断拆成可观察事实。

```text
差：这套流程偏重。
好：短篇临时生成用不上这些命令；长篇连载时，角色、伏笔和世界观才需要单独维护。
```

```text
差：这个治理工具很重。
好：接入前要先配置身份、策略、沙箱和审计；只做内部 demo 时，未必需要全部打开。
```

## 2.2 英文条件状语

触发：句子用 `A 一旦 B，就 C`、`当 A 进入 B 之后，真正的问题是 C` 起手，前半句塞进多个对象、范围或风险。

判断：英文常把条件从句放在前面，中文也可以写条件，但技术介绍里更稳的做法是先写真实动作或真实麻烦。条件太长时，主语、谓语和结果被推迟，读者先读到一串范围，后面才知道作者到底要说什么。

改法：先写动作，再补条件和后果。

```text
差：Agent 一旦开始碰文件、命令和外部 API，问题就不只是能不能执行，还包括权限和边界。
好：让 agent 调命令前，先把权限边界定清楚。它能改哪些文件、能不能访问外部 API、失败后怎么回滚，都要提前写进规则。
```

## 2.2.1 前置条件逗号

触发：句子把时间、条件或读者范围放在主动作前面，再用逗号隔开，例如 `下载模型前，先...`、`刚补 Agent 基础的人，先...`、`长期改同一个项目时，它...`。

判断：长状语前置本来就要少用。确实要写时，中间再加逗号，会把主动作往后推，读者先读到一段条件，再等真正谓语出现。技术介绍和课程介绍里，这种停顿很容易变成英文从句感。

改法：优先把主动作提前；如果保留前置条件，就去掉逗号，让条件和动作连在一起。

```text
差：刚补 Agent 基础的人，先按章节跑工具调用、规划和多 agent 协作。
好：刚补 Agent 基础的人可以先按章节跑工具调用、规划和多 agent 协作。
```

```text
差：下载模型前，先查本机硬件、模型规格和 provider 选择。
好：下载模型前先查本机硬件、模型规格和 provider 选择。
```

## 2.3 伪主语结构

触发：句子开头是 repo 名、产品名或项目名，后面接 `先看`、`看看`、`重点看`、`值得看`、`值得拆` 这类读者动作。

判断：项目名通常不是动作执行者。`BilldDesk 先看远控流程` 的问题不是不够口语，而是主语和谓语不匹配。真正执行 `看` 的人是读者或省略的 `我们`，项目名应该放进宾语内部，成为 `BilldDesk 的远控流程`。

改法：按真实动作重写。

```text
我们先看 BilldDesk 的远控流程。
```

或改成话题句。

```text
BilldDesk 的远控流程可以拆成建连、传画面和接管鼠标键盘三步。
```

## 2.4 数量前置的抽象麻烦句

触发：句子写成 `X 一多，麻烦 / 问题 / 风险 / 难点通常出在 Y`，尤其是 X 里塞进模型、provider、依赖、配置、平台、工具、规则等多个对象。

判断：这类句子表面像中文口语，实际还是英文式条件从句。它先抛数量变化，再抛抽象麻烦，最后才说检查点。读者先读到一串范围，却不知道真正动作是什么。

改法：先写具体动作，再写检查点。把 `麻烦通常出在` 改成可执行的检查路径。

```text
差：模型和 provider 一多，麻烦通常出在下载前。
好：下载模型前，先查本机硬件、模型规格和 provider 选择。能跑哪些、跑到什么规格，结果先摆出来。
```

## 2.5 命令容器翻译腔

触发：句子写成 `把 A 放到 / 放进 一个命令 / command 里查`。

判断：命令不是一个装东西的容器。中文里更自然的关系是“用一个命令查清什么”，或者“一个命令同时查几项”。如果继续保留 `把 A 放进命令里`，句子会像从英文产品说明硬翻过来。

改法：把命令改成动作工具，补出查询对象和结果。

```text
差：llmfit 把 models、providers 和硬件限制放到一个命令里查。
好：llmfit 可以用一个命令查本机硬件、模型规格和 provider 选择。
```

## 2.6 后台评审泄漏成正文

触发：最终文案里出现 `这句话要...`、`因为它写的是...`、`句子在说...`、`这里的“了”更明显...`、`文案里要写出...` 这类规则解释或评审判断。

判断：这些内容属于后台审核、结构标注或报告，不属于可发布正文。用户要的是产品更新稿时，正文只能写产品事实、状态变化、使用入口和边界；不能把为什么这样写、哪个词为什么保留这类判断交出去。

改法：保留被判断后的正文，删除评审语言。若需要说明规则，放到报告或结构标注稿里，并清楚标为非正文。

```text
差：这句话要带“了”，因为它写的是接入动作已经发生。
好：Google 这次把 Managed Agents 接进了 Gemini API。
```

## 2.7 抽象判断骨架后置

触发：句子写成 `要判断 / 决定 / 评估 X，还得 / 还要 / 需要看 Y`，或者先写 `不稀奇`，后面接 `真正 / 关键 / 重点 / 决定` 这类抬高判断。

判断：这类句子先摆一个抽象评估框，再把具体检查项放在后面，读起来像英文转折或产品页论证。中文里更自然的推进是先写具体检查动作，再把能不能用、要不要接入、敢不敢上线放到后面当结果。

改法：把 Y 改成具体动作清单，把 X 放到句末。`不稀奇` 本身不必硬禁，但不能拿它开启抽象转折。

```text
差：团队要决定能不能用，还得看权限怎么批、记录怎么留、失败后谁接手。
好：团队评估 agent 时应该一起看权限审批、运行记录和失败后的接手方式，再决定能不能接进业务。
```

```text
差：页面能动不稀奇。真正重要的是权限、记录和接手。
好：团队评估 agent 时应该一起看权限审批、运行记录和失败后的接手方式，再决定能不能接进业务。
```

如果句子已经没有明确动作方，不能继续写成 `页面能跑，只说明...。先看...`。这会缺主语，也会把判断和动作强行串起来。

```text
差：页面能跑，只说明 demo 做出来了。先看权限怎么批、记录怎么留、失败后谁接手，再决定这个 agent 能不能接进业务。
好：团队评估 agent 时应该一起看权限审批、运行记录和失败后的接手方式，再决定能不能接进业务。
```

## 2.8 字幕和通知压缩句

触发：视频字幕、推送通知或短消息里出现 `候补又对错了`、`已改线上` 这类为了短而省掉关系的句子；活动通知里出现 `现改为...了`、`届时也可观看` 这类公告腔收束。

判断：短文案可以省字，但不能省到让读者分不清动作。`候补又对错了` 可能被理解成“核对错了”，也可能是“名单对不上”。`已改线上` 少了“为”，像后台字段压缩。`现改为...了` 是书面通知和口语完成态叠在一起。`届时也可观看` 在已经说明回放会发出时是重复信息。

改法：把状态写清楚，宁可多一个词。

```text
差：候补又对错了。
好：候补名单又对不上了。
```

```text
差：今晚分享已改线上。
好：今晚分享改为线上。
```

```text
差：因场地空调临时检修，现改为线上直播了。
好：因场地空调临时检修，这次改为线上直播。
```

```text
差：回放将在分享结束后的第二天发出，届时也可观看。
好：回放会在分享结束后的第二天发出。
```

### 2.8.1 活动通知警报腔

触发：普通活动变更通知用 `各位...注意` 开头。

判断：这像广播、课堂纪律提醒或安全警报。普通活动通知更自然的写法是直接说活动发生了什么变化，再告诉参与者要不要操作。

改法：

```text
差：各位开发者注意，原定 6 月 5 日晚的分享改为线上直播。
好：6 月 5 日晚的分享改为线上直播。
```

## 2.9 硬凑动词和容器关系

触发：句子写成 `归好发言和结论`、`把处理结果发到短信里`、`这份工作会做...`、`工作内容是...页面 / 后台`、`你会负责活动报名页、候补名单页面和运营后台的页面开发`、`研发周五给...接口`、`保存后进入...设置，打开...`。

判断：这些句子不是单纯不够正式，而是动作关系不对。`归好` 不是正常中文搭配；短信不是容器；工作不是做页面的主语；工作内容也不是一个页面或后台对象；把 `页面 / 后台 / 系统 / 模块` 混在一个并列里，再用 `页面开发 / 前端开发` 当后缀，也只是把坏句换了壳；`给接口` 缺少交付动词；上手引导里的动作顺序被粘成一串。

改法：换成真实动作和自然搭配。

```text
差：它会先转写录音，再按议题归好发言和结论。
好：它会先转写录音，再按议题整理发言和结论。
```

```text
差：系统会在两个工作日内把处理结果发到短信里。
好：系统会在两个工作日内发短信告诉你处理结果。
```

```text
差：这份工作会做活动报名页、候补名单页面和运营后台。
好：你会负责活动报名页、候补名单页，以及运营后台里活动管理相关页面的开发。
```

```text
差：工作内容是活动报名页、运营后台和候补名单页面。
好：工作内容包括开发活动报名页、候补名单页，以及运营后台里的活动管理页面。
```

```text
差：你会负责活动报名页、候补名单页面和运营后台的页面开发。
好：你会负责活动报名页、候补名单页，以及运营后台里活动管理相关页面的开发。
```

```text
差：研发周五给候补名单接口。
好：研发周五给出候补名单接口。
```

```text
差：保存后进入报名页设置，打开候补名单和短信提醒。
好：保存后在报名页设置里打开候补名单和短信提醒。
```

## 3. 高风险骨架

这些结构不一定永远错，但在技术推荐、工具介绍、自动化摘要里经常带出翻译腔。出现时必须检查有没有具体动作：

- `通过 A 实现 B`
- `基于 A 的 B`
- `围绕 A 构建 B`
- `提供 A 能力`
- `具备 A 特性`
- `面向 A 场景`
- `用于 A 的 B`
- `以 A 为核心`
- `完整度比较高`
- `适合拿来研究`
- `可以作为参考`
- `开箱即用`

重写原则：

```text
把抽象关系改成读者动作、工具动作或结果。
```

差：

```text
它提供面向多 agent 协作场景的上下文管理能力。
```

好：

```text
多个 agent 轮流改同一个项目时，它能把背景和状态留住。
```

## 4. 假口语

少用或禁用这些看似口语、实际模板感很强的表达：

- `真要`
- `真想`
- `真做`
- `真用`
- `真拿`
- `真碰`
- `说白了`
- `有点意思`
- `有点东西`
- `这波`
- `稳了`
- `硬核`

如果想表达条件，用 `如果...`。如果想表达读者对象，用 `准备...的人`、`长期做...的人`、`做 X 的人`。

## 5. 工具项目定义句

触发：介绍工具、开源项目、GitHub repo、README 项目。

判断：第一句默认应该用带量词的项目名定义句。`XX 是一个 / 一款 / 一套 / 一种……的……` 能先给陌生项目建立坐标，这是正常中文介绍，不是英文腔。问题出在三类写法：一种是用 `这个项目 / 这个工具` 隐掉项目名，一种是少了 `一个 / 一款 / 一套 / 一种` 这类量词，另一种是定义后堆宣传词、功能词和空价值。

改法：

- 第一用项目名，不用 `这个项目 / 这个工具` 代替。
- 谓语用 `是`，宾语前带量词，再写工具类型、用途或所属关系。
- 第二句开始写它处理什么动作、有什么边界。
- 禁止用前置状语开头绕开定义句。

可用：

```text
Scrapling 是一个 Python 网页抓取库。页面结构变了，它会按相似度把之前抓过的元素找回来。
```

不可用：

- `这个项目是一个...`
- `这个工具是一个...`
- `该项目...`
- `这是一款...`
- `这个方向...`
- `这个思路...`

也不可用：

```text
Scrapling 是一个开箱即用的爬虫框架，具备完整能力，适合复杂场景。
```

## 5.1 前置状语过载

触发：一批介绍连续用 `……时`、`……后`、`……一次` 这类前置状语起手。

判断：单句里条件或时间状语可以放在前面；连续三条都这样写，就不是自然中文，而是把英文条件从句换成中文开头。它会让每条都先绕一圈条件，再进入项目本身，读起来比朴素定义句更别扭。

改法：

- 工具项目介绍第一句不使用前置状语开头。
- 先用 `项目名 + 是 + 量词 + 类型 / 用途 / 所属关系` 建立对象。
- 第二句再写场景、动作或边界。

差：

```text
有一批 PDF 要处理时，……
网页结构改一次，……
团队把 agent 接进开发流程后，……
```

好：

```text
MarkItDown 是微软做的一个文档转 Markdown 工具。
Scrapling 是一个处理网页结构变化后元素定位的 Python 库。
Compound Engineering Plugin 是一个把 brainstorm、plan、work、review 和 compound 做成工程命令的插件。
```

## 6. 宾语前置推荐句

拒绝：

```text
12-factor-agents 这份清单可以先读。
tinyhumansai/openhuman 可以拿来拆。
Open-Generative-AI 值得先看。
```

改成：

```text
如果我们想让 agent 进生产流程，可以先看一下 12-factor-agents 这份清单。
可以拆一下 tinyhumansai/openhuman 的角色设计。
如果你想自己搭一个 AI 图像和视频生成工作室，可以先看 Open-Generative-AI。
```

推荐句里，读者动作通常先出现，被推荐对象放在动词后面。

## 7. 抽象判断降级

遇到这些词，检查它们有没有替代具体动作：

- `价值`
- `方向`
- `思路`
- `能力`
- `链路`
- `生态`
- `闭环`
- `体系`
- `落地`
- `信号`

差：

```text
这类工具的价值就在这。
```

好：

```text
它能把项目背景留住，下次不用从头解释一遍。
```

## 8. 结构优先级

审查顺序：

1. 先看句子主干是不是中文。
2. 再看项目名位置是不是自然。
3. 再看动词和结果是不是具体。
4. 最后才删词。

只删禁词但保留英文骨架，视为未通过。

## 9. Validator 交接

能机器化的规则应该沉淀到 validator：

- 明确禁句
- 明确正则结构
- 字段状态要求
- 批次重复度阈值
- 编码损坏检查

但 validator 只能做最后拦截。真正的核心仍然是：

```text
英文事实 -> 中文事实稿 -> 中文句法检查 -> 正文 -> 批次去模板化 -> validator
```

硬黑名单见 `blacklist_patterns.md`。命中 hard blacklist 时，不允许 `copyCritique.status = "pass"`。
