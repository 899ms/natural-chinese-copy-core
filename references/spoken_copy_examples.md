# 口语化中文好坏例

目标：用对照样例训练语体转换，而不是机械缩写。

## 1. 打招呼

Facts:

- 早上见面。
- 想问对方找自己做什么。

formal:

```text
早上好，请问有什么需要我帮忙的吗？
```

plain:

```text
早上好，有什么我能帮你的？
```

casual:

```text
早，有啥需要帮忙的？
```

close-chat:

```text
早，干啥？
```

判断：

- `早，干啥？` 只适合熟人或强上下文。
- 对陌生人直接这样说会显得冲。

## 2. 推荐工具

Facts:

- 一个工具能让 agent 记住项目背景。
- 用户下次继续任务时不用重讲。

formal:

```text
该工具用于保存项目上下文，便于 agent 在后续任务中继续使用已有背景信息。
```

plain:

```text
它能把项目背景留住。下次继续改同一个项目时，不用从头解释一遍。
```

casual:

```text
这个挺适合长期改项目的人。它能把背景记住，下次不用重新讲。
```

close-chat:

```text
能用。主要就是记背景，省得每次从头说。
```

差：

```text
这个工具通过上下文管理能力提升 agent 协作效率。
```

问题：

- 英文产品页骨架。
- 名词化过重。
- 不像任何真实语体。

## 3. 解释限制

Facts:

- 这个方案适合长期项目。
- 一次性 demo 不必使用。

formal:

```text
如果只是一次性 demo，不需要接入完整流程。该方案更适合长期维护的项目。
```

plain:

```text
只做一次 demo 的话不用上这一套。长期改同一个项目时，它才比较有用。
```

casual:

```text
一次性 demo 就别折腾这个了。长期项目再用，比较值。
```

close-chat:

```text
demo 别上。长期项目再说。
```

## 4. 问用户要信息

Facts:

- 需要知道用户是想看配置问题还是 API 问题。

formal:

```text
请确认你希望优先排查配置问题，还是 API 调用问题。
```

plain:

```text
你想先看配置，还是先看 API 调用？
```

casual:

```text
先看配置还是 API？你定一个。
```

close-chat:

```text
配置还是 API？
```

## 5. 口语化失败

差：

```text
咱就是说，这个工具有点东西，直接狠狠提升效率。
```

问题：

- 只有口头禅，没有事实。
- `提升效率` 是空判断。
- 熟悉感是假的。

好：

```text
这个可以看。它能让 agent 自己查 Console 和 Network，少掉很多来回猜的时间。
```
