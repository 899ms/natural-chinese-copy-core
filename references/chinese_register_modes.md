# 中文语体模式

目标：把正式、平实、日常、熟人聊天拆成可执行的句法选择。

## 1. formal

适用：

- 报告
- 公告
- 合同和政策说明
- 对外邮件
- 面向陌生人的专业文本

结构特征：

- 句子完整。
- 主语、对象、条件写清楚。
- 少省略。
- 少情绪词。
- 连接关系明确。

不要写成官腔：

```text
为进一步提升能力、完善体系、推动落地...
```

优先写：

```text
这次调整主要解决三个问题：权限不清、状态缺失、失败后没人接手。
```

## 2. plain

适用：

- 默认技术解释
- 产品说明
- 推荐语
- 用户帮助
- 普通社交平台长文

结构特征：

- 句子清楚，但不端着。
- 读者、场景、动作优先。
- 可以省掉不必要的礼貌套话。
- 抽象判断后必须接具体动作。

例：

```text
如果你长期让 agent 改同一个项目，最烦的是每次都要重新讲背景。这个工具能把背景留住，下次接着改会省很多事。
```

## 3. casual

适用：

- 群聊
- 朋友圈
- 轻松推荐
- 内容平台短评

结构特征：

- 短句更多。
- 可以省主语。
- 可以用 `这个可以看`、`挺适合`、`先别急着上` 这类日常判断。
- 语气可以轻，但事实不能虚。

例：

```text
这个可以看一下。它解决的是 agent 老忘项目背景的问题，下次回来不用从头讲。
```

风险：

- 不要堆 `说白了`、`有点东西`、`这波稳了`。
- 不要靠网络口头禅制造熟悉感。

## 4. close-chat

适用：

- 熟人聊天
- 上下文已经很清楚的连续对话
- 用户要求“直接点”“随便说”

结构特征：

- 大量省略。
- 短问短答。
- 先给结论。
- 语气允许更直接，但不能冒犯。

例：

```text
可以。这个就是帮 agent 记项目背景的，下次不用重讲。
```

更熟：

```text
能用。主要就是记背景，省得每次从头说。
```

风险：

- 上下文不足时不要省太多。
- 公开文案不要默认用这个模式。
- 直接不等于粗糙。

## 5. 语体转换不是缩写

错误做法：

```text
formal: 请问您是否需要我提供进一步帮助？
casual: 请问需要帮助？
close-chat: 帮助？
```

正确做法：

```text
formal: 请问您是否需要我继续协助处理？
plain: 还需要我继续看吗？
casual: 要我继续看吗？
close-chat: 还看吗？
```

语体变化改变的是信息组织、关系距离和省略程度，不是机械删字。
