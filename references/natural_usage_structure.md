# 自然用语结构

目标：学习真实中文如何顺着上下文说话。自然不是随便，不是短，也不是网络词多。

## 1. 基本单位

自然用语常按“话轮”推进，而不是按完整书面段落推进。

常见话轮：

- `回应`: 先接住对方的话。
- `确认`: 把关键对象或问题点复述一遍。
- `补充`: 加一条新信息。
- `追问`: 问缺失条件。
- `提醒`: 给风险或边界。
- `转向`: 把话题带到下一步。
- `收束`: 给明确动作。

## 2. 回应结构

触发：对方刚提出需求、抱怨、质疑或给出材料。

判断：如果直接开始讲定义，会显得像说明书。

改法：先接住对方动作，再给下一步。

差：

```text
BilldDesk 是一个远程桌面控制工具。
```

好：

```text
看 BilldDesk，先别从技术栈开始。先看它怎么让浏览器连上电脑、看到画面、接管鼠标键盘。
```

## 3. 确认结构

触发：事实材料很散，包含多个技术名词和功能点。

判断：直接罗列会像 README 摘要。

改法：先确认主问题，再分组。

```text
这个项目主要看三组东西：设备怎么连，控制和画面怎么走，多台设备怎么管。
```

## 4. 补充结构

触发：一句话已经说清主动作，但还缺限制或证据。

判断：连续使用 `另外 / 此外 / 同时` 时，句子通常只是在堆信息，没有说明新信息和前一句的关系。

改法：补充句只加一个新信息。

差：

```text
此外，它还支持文件传输、多屏、设备分组、屏幕墙和批量群控。
```

好：

```text
远控之外，它还留了文件传输入口。多台机器一起管时，再看设备分组和屏幕墙。
```

## 5. 追问结构

触发：用户目标不明，或语体、平台、受众不明。

判断：一次问太多条件时，用户不知道先回答哪一个。

改法：只问影响最大的一件事。

```text
这篇是发群里，还是发到公开账号？
```

熟人语境：

```text
发哪儿？
```

## 6. 提醒结构

触发：工具不稳定、权限敏感、生产风险、事实不完整。

判断：`需要自行评估` 只给态度，没有告诉读者该检查什么。

改法：写清要检查的对象。

```text
README 说开源版还不是稳定版。部署前先压连接稳定性，再查权限控制和设备管理。
```

## 7. 转向结构

触发：从事实介绍转到建议、从问题转到行动。

判断：`基于此 / 进一步来说 / 因此可以看出` 会把普通下一步写成报告腔。

改法：用下一步动作接。

```text
看源码时，先从建连开始。画面出来以后，再看控制指令和文件传输。
```

## 8. 收束结构

触发：段落末尾需要结束。

判断：`值得关注 / 适合研究 / 后续观察` 只给评价，没有给读者下一步。

改法：给读者下一步动作或明确边界。

```text
想拆远控实现，先看它的建连和控制。想找稳定商用工具，先别把它放进正式环境。
```

## 9. 自检

写完问：

1. 第一反应像人在回应，还是像文档在定义？
2. 每个分句有没有新信息？
3. 边界有没有具体对象？
4. 收尾有没有给下一步？
5. 有没有靠连接词硬拼段落？
