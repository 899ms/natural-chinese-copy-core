# 规则蒸馏方法

目标：把论文、坏例、人工经验和 validator 日志变成能执行的中文句法规则。

## 1. Reference 的作用

`references/` 不是原始资料仓库。

它只存三类东西：

- 已蒸馏成动作的规则
- 可追溯的来源摘要
- 能回归测试的好坏例

`SKILL.md` 只保留每次调用都必须执行的协议。细则、证据、样例放在 reference 里，调用时按需读取。

## 2. 蒸馏公式

每条新规则必须走完这条链：

```text
资料来源 -> 语言现象 -> 文案症状 -> 重写动作 -> 可拦截信号 -> 评测样例
```

示例：

```text
译文中文更常见长 NP + 的 修饰结构
-> 文案里出现连续定语和多个 的
-> 读者要等到句尾才知道中心动作
-> 拆出中心动作，把修饰语改成下一句
-> validator 检查连续 的、长名词短语、中心动词缺失
-> 加入 bad / pass 样例
```

## 3. 规则准入标准

新规则进入 skill 前，必须满足：

- 能指出具体句子问题，不只是审美判断。
- 能写出重写动作，不只是说“更自然”。
- 至少有一个坏例和一个改写例。
- 不把正常中文结构一刀切禁掉。
- 能判断适用边界，例如“硬拒绝”“高风险”“批次风险”。
- 能写成 `触发 -> 判断 -> 改法`，不能只写成口号。

不满足这些条件的内容，只能留在研究笔记里，不能进入执行规则。

## 4. 资料来源分层

优先级从高到低：

1. 中文语言学和翻译腔研究：用于发现稳定句法现象。
2. 真实业务坏例：用于发现当前场景里的高频问题。
3. validator 拦截日志：用于发现可机器化的模式。
4. 批次输出对比：用于发现模板化和同质化问题。
5. 个人偏好：只能作为待验证假设，不能直接变成硬规则。

## 5. 从论文到规则

读论文时不要摘长段原文，只抽这四项：

```text
研究结论：
对中文文案的影响：
可观察症状：
重写或拦截方式：
```

只有最后两项能进入写作流程。

## 6. 从坏例到规则

处理坏例时按这个顺序标注：

1. 句子主干是什么？
2. 读者是谁？
3. 谓语动词是不是具体动作？
4. 宾语或结果是不是具体？
5. 项目名是不是被硬塞成主语？
6. 有没有英文式长定语、名词化、转折骨架？
7. 这个问题能不能用 validator 捕捉？

## 7. 规则落位

- 通用句法规则：写入 `chinese_sentence_structure.md`。
- 翻译腔和 AI 腔模式：写入 `anti_translationese_patterns.md`。
- 批次同质化规则：写入 `batch_repetition_review.md`。
- 规则写法约束：写入 `rule_language_guard.md`。
- 好坏例：写入 `chinese_tool_copy_examples.md` 或 `copy_eval_rubric.md`。
- 资料来源摘要：写入 `research_sources.md`。
- 每次都必须执行的短流程：才写入 `SKILL.md`。

## 8. 不做的事

不要：

- 把论文原文整段复制进 skill。
- 把禁词表当成核心能力。
- 因为某个词“看起来 AI”就永久封禁。
- 把场景规则写成全中文写作的绝对规则。
- 为了显得自然而制造假口语。
- 把规则写成 `要 A，不要 B`、`打通链路`、`跑通流程` 这类口号。
