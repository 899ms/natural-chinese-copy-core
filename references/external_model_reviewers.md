# 外部模型评审参与规则

外部模型只能做中文文案自然度复核，不能替代本 skill 的生成门禁、validator、事实校验和可发布性人工复核。

## 启用条件

外部评审默认不启用。只有用户明确要求外部模型、多模型讨论或指定某个 reviewer 参与时，才读取本文件。

上传分享版不得假设用户拥有某个指定模型、MCP server、私有 provider 或任何本机密钥。

## 参与方状态

每个外部参与方都必须记录状态：

- `pass`：真实返回了可用审稿内容。
- `configured`：配置存在，但本轮没有产生可用审稿内容。
- `unavailable`：当前会话没有对应工具或凭据。
- `error`：工具可调用，但请求失败或返回不可用内容。

不得把 `configured`、`unavailable` 或 `error` 写成已经参与审稿。

## 密钥边界

- API key、Bearer token、私有 endpoint 和本机配置路径不得写进仓库、样本、报告或公开文档。
- 外部工具输出必须脱敏后才能进入 `.tmp/` 或 `pdoc/`。
- 如果某个外部 reviewer 需要本机配置，配置说明留在用户自己的环境里，不作为本 skill 的默认依赖。

## 调用顺序

1. Codex 先跑本地 validator、事实校验和可发布性检查。
2. 外部 reviewer 只看已经通过本地硬门禁的候选稿。
3. 外部 reviewer 的原始意见先落到 `.tmp/` 或报告草稿，不直接写进规则文件。
4. Codex 对每条意见做裁决。
5. 只有用户确认后的新问题，才能进入 feedback 样本、publishability 样本、legacy registry 或 validator。

## 裁决层

外部模型的每条意见必须先由 Codex 裁决，再决定是否进入样本或规则。禁止把模型输出直接当成结论。

裁决状态只允许使用：

- `accepted`：问题明确，且不和本地规则冲突；可以进入改稿或样本。
- `misjudgment`：模型误判，例如把工具介绍首句里的量词判成冗余；不进入样本或规则。
- `sample-only`：问题依赖文本类型或语境，只进入反馈样本或可发布性样本，不进 hard rule。
- `hard-rule-candidate`：坏句稳定、边界清楚、可机器化；用户确认后才能进 validator。
- `boundary`：建议可能改事实、改语气过度或只适合某个渠道，只能作为讨论记录。

每轮外部评审结束后，必须输出采纳表：

| 来源 | 原句 | 模型问题 | Codex 裁决 | 去向 |
| :--- | :--- | :--- | :--- | :--- |
| reviewer name | 具体坏句 | 问题摘要 | accepted / misjudgment / sample-only / hard-rule-candidate / boundary | 改稿 / 样本 / validator / 不采纳 |

## 审稿重点

- 工具 / 开源项目介绍：先检查首句是否是 `项目名 + 是 + 量词 + 类型 / 用途`。外部模型如果要求删除这个量词，默认先按 `misjudgment` 处理。
- 产品更新：检查新变化、用户会看到什么、是否需要操作；避免把短帖写成纯功能列表。
- 活动通知：检查时间、形式、读者动作和称呼是否自然。
- 社媒短评：检查是否有具体观察和证据，避免 `真正重要的是`、`关键是` 这类抽象抬高。
- 事故通知：检查影响对象、当前状态和用户是否需要操作，避免只写内部故障标签。
- 谓语真实动作：重点看主语能不能执行谓语；任何虚假动作、翻译腔动词、空方向动词、悬空改善词或容器动词都要标出来。
