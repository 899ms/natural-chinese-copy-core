# 平台语体

目标：同一句事实放到不同平台，中文结构要跟着变。不要用一个“自然中文”模板覆盖所有场景。

## 1. 技术社区

适用：GitHub、V2EX、掘金、技术博客、开发者群。

结构：

```text
问题对象 -> 实现路径 -> 可拆模块 -> 风险边界
```

写法：

- 技术名词可以保留，但必须放进动作。
- 少写情绪判断。
- 边界要具体到稳定性、权限、部署、维护。

例：

```text
看 BilldDesk，先拆远控流程。浏览器、桌面端和 Android 端都在项目里，控制和观看走 WebRTC，文件传输和设备管理有单独入口。
```

## 2. 小红书式种草

适用：经验分享、轻推荐、生活化工具。

结构：

```text
真实困扰 -> 试了什么 -> 哪一步省事 -> 不适合谁
```

风险：

- 不要硬套 `家人们 / 真的绝 / 狠狠`。
- 工具类内容要保留限制，不能只写情绪。

## 3. B站 / 弹幕式表达

适用：口播、短评、视频脚本。

结构：

```text
结论先行 -> 画面动作 -> 槽点或边界 -> 下一步看点
```

写法：

- 句子短。
- 动作感强。
- 能听懂比看起来漂亮更重要。

## 4. 微博式短评

适用：公开短评、热点跟进。

结构：

```text
判断 -> 证据 -> 边界
```

风险：

- 容易写成口号。
- 不要用空转折制造态度。

## 5. 知乎式解释

适用：解释原因、拆问题、讲判断依据。

结构：

```text
先限定问题 -> 分层解释 -> 给例子 -> 收边界
```

写法：

- 可以长一点，但每段只解决一个问题。
- 不要堆“本质上 / 核心在于 / 归根结底”。

## 6. 朋友圈

适用：熟人弱公开场景。

结构：

```text
一句真实判断 -> 一点具体事实 -> 一句轻边界
```

写法：

- 比群聊完整，比公开文章松。
- 不要写太像广告。

## 7. 群聊

适用：熟人或半熟人即时沟通。

结构：

```text
结论 -> 原因 -> 要不要继续看
```

例：

```text
BilldDesk 可以拆。它把网页、桌面端和安卓端都放一起了，远控这块能看到完整实现。不过 README 说还不是稳定版，别直接上生产。
```

## 8. 平台选择自检

1. 这段要发到哪里？
2. 读者是陌生人、同行、熟人，还是混合人群？
3. 这个平台更看重动作、经验、态度，还是解释？
4. 能不能保留事实清楚度？
5. 有没有用了已经过时的网络词？
